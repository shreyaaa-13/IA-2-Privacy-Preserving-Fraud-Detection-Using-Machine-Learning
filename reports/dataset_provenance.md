## 2. Dataset Structure and Feature Dictionary

The raw dataset contains **284,807 transaction records** recorded over a consecutive 48-hour period in September 2013 by European cardholders.

| Column Name | Data Type | Representation & Description | Transformation & Anonymization Status |
| :--- | :--- | :--- | :--- |
| `Time` | Float64 | Elapsed time in seconds between this transaction and the first transaction in the dataset. Total duration: 172,792 seconds (~48 hours). | Unscaled raw timestamp. Contains diurnal patterns. |
| `V1` to `V28` | Float64 | 28 continuous numerical features representing the principal components of sensitive financial attributes (e.g., merchant ID, cardholder location, terminal ID). | **PCA-transformed:** Standardized principal components resulting from orthogonal linear projection. Original attributes redacted. |
| `Amount` | Float64 | Transaction charge amount in local currency (Euros). Range: $0.00 to $25,691.16. Highly skewed (median: ~€22.00). | Raw continuous monetary value. Not normalized in raw CSV; preprocessed using `RobustScaler` in pipeline. |
| `Class` | Int64 | Ground-truth binary target label: `1` indicates a fraudulent transaction, `0` indicates a legitimate transaction. | Binary ground-truth indicator. |

## 3. Data Distribution and Extreme Class Imbalance

- **Total Transaction Count:** 284,807 records
- **Legitimate Transactions (`Class = 0`):** 284,315 records (99.8273%)
- **Fraudulent Transactions (`Class = 1`):** 492 records (0.1727%)
- **Imbalance Ratio:** ~578 legitimate transactions for every 1 fraudulent transaction.
- **Missing Values:** Exactly 0 missing (null) values across all columns.
- **Duplicate Records:** 1,081 duplicate transactions in raw data (consistent with high-frequency micro-authorizations; retained or logged during preprocessing).

## 4. Responsible Data Use and Ethical Privacy Protocols

### Anonymization and De-Anonymization Restrictions
1. **PCA Redaction:** The original transaction attributes (such as cardholder names, credit card numbers, merchant categories, and geolocation coordinates) were transformed using Principal Component Analysis (PCA) prior to public release to protect proprietary banking records.
2. **Identity Non-Recovery:** Researchers and students utilizing this dataset **must not attempt to reverse-engineer, re-identify, or reconstruct individual cardholder identities** through linkage attacks with external auxiliary datasets.
3. **No Synthetic Misrepresentation:** Synthetic data generated by the software test harness (`src/synthetic_data.py`) is strictly for offline pipeline validation and unit testing; it is never claimed as real cardholder behavior.

## 5. Lawful Dataset Acquisition Instructions

To respect data distribution rights and ensure lightweight project packaging, the raw `creditcard.csv` file (~150 MB uncompressed) is **excluded from the submission ZIP archive**.

### Option A: Manual Download via Web Browser (Recommended for Beginners)
1. Open the official Kaggle dataset page:  
   `https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud`
2. Click the **Download** button in the upper right corner (requires a free Kaggle user account).
3. Extract the downloaded `archive.zip` file on your computer.
4. Move the extracted `creditcard.csv` file into the project directory:  
   `IA1_Fraud_Detection_Privacy/data/creditcard.csv`

### Option B: Download via Official Kaggle CLI
If you have configured your local Kaggle API token (`~/.kaggle/kaggle.json`):
```bash
cd IA1_Fraud_Detection_Privacy/data
kaggle datasets download -d mlg-ulb/creditcardfraud --unzip
```

### Option C: Offline Verification Mode (No Download Required)
If you do not have immediate internet access or Kaggle credentials, you can execute the entire project offline:
```bash
python run_experiments.py --mode test
```
The pipeline automatically generates a synthetic test dataset (`data/synthetic_creditcard.csv`) matching the identical 31-column schema, verifying every script, test, plot, and metric cleanly.
